# Workflow: Improve Existing Work

## Route here when
The user wants to revise, refactor, extend, optimize, migrate, polish, or otherwise improve an existing artifact or project.

## Steps
1. Inspect the actual artifact, structure, version, constraints, and current state before proposing edits.
2. Identify existing user changes and preserve unrelated work.
3. Establish baseline behavior and acceptance criteria where possible.
4. Separate requested changes from optional improvements.
5. Assess compatibility, regression risk, migration needs, and rollback.
6. Resolve material ambiguity and request approval for the proposed scope.
7. Make small, reviewable changes.
8. Compare against baseline; run relevant regression checks.
9. Perform requirements and quality review.
10. Report changed files, behavior changes, compatibility, evidence, and known regressions/limitations.

Never silently replace the user's architecture, style, conventions, or working implementation merely because an alternative is preferred.
