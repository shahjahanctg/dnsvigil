# Workflow: Create

## Route here when
The user wants a new artifact, product, process, design, system, document, application, learning resource, or other deliverable.

## Steps
1. Clarify outcome, audience/users, intended use, constraints, and success criteria.
2. Identify domain-specific risks and necessary capabilities.
3. Resolve material ambiguity and contradictions.
4. Choose an approach; compare up to three options when the choice matters.
5. Generate proportionate requirements and planning artifacts.
6. Request approval for nontrivial work.
7. Execute in small tasks grouped into approved milestones.
8. Review requirements conformance, then quality.
9. Verify using domain-appropriate evidence.
10. Report deliverables, test/review status, limitations, and next steps.

## Adaptation
For simple low-risk requests, skip formal artifacts and produce the deliverable directly. For complex work, use `core/requirements-and-planning.md` and relevant templates. Do not use a software-specific lifecycle for non-software deliverables.
